# AWS Network Firewall がフォワードプロキシ機能として再提供開始

フォワードプロキシ機能の統合提供を開始

**発表日: 2026年8月4日**

---

## 概要

### 主な変更点

- **フォワードプロキシ統合**: AWS Network Firewall に明示的フォワードプロキシ機能が統合
- **機能統合**: 2025年11月のプレビュー版を独立製品から統合
- **既存機能の保持**: すべてのファイアウォール機能をフォワードプロキシモードで利用可能
- **単一ポリシー管理**: 透過型ファイアウォールと明示的プロキシを同一ポリシーで管理
- **プレビュー中は無料**: 米国東部（オハイオ）リージョンで無料提供

---

## 前提・背景

### 自社管理プロキシの課題

- **デプロイとスケーリングの複雑さ**: EC2/コンテナベースのプロキシフリートの運用負担
- **パッチ管理**: セキュリティアップデート対応の手間
- **コスト増加**: インフラストラクチャ管理に伴うコスト
- **運用ワークロード**: セキュリティ以外の運用業務が増大

### 関連トレンド

- ネットワークセキュリティのマネージド化へのニーズ拡大
- データ流出防止（DLP）の重要性増加
- 集中型セキュリティ制御の需要増加

---

## 機能の進化と統合

### 2025年11月 → 2026年8月の変化

| 項目 | 2025年11月 | 2026年8月 |
|------|-----------|----------|
| 形態 | 独立製品（プレビュー） | Network Firewall 統合機能 |
| 展開モード | explicit-mode | no-source-preservation |
| 既存ルールの利用 | 限定的 | 全機能サポート |
| ポリシー共有 | 別個のポリシー | 統一ポリシーで管理 |
| ユースケース | プロキシ専用 | 透過型 + 明示的の併用 |

---

## 主な機能

### 利用可能なセキュリティ機能

- **マネージドルールグループ**: 脅威シグネチャの自動更新
- **アクティブ脅威防御**: ゼロデイ脅威への対応
- **Geo-IP フィルタリング**: 地域ベースのアクセス制御
- **URL・ドメインカテゴリフィルタリング**: コンテンツベースの制限
- **コンテナ属性ベースルール**: Amazon EKS/ECS 統合

### デプロイメント方式

- no-source-preservation 展開モード
- NAT ゲートウェイへの接続
- PrivateLink エンドポイント経由のトラフィック処理
- クライアント明示設定（プロキシ指定）

---

## ユースケース

### 適用対象組織

1. **集中型セキュリティ制御が必要な企業**
   - 複数の VPC でのセキュリティポリシー統一
   - コンプライアンス要件の厳格化

2. **データ流出防止（DLP）を強化したい組織**
   - 外部への機密情報送信の防止
   - マルウェア注入対策の強化

3. **プロキシ運用を簡素化したい組織**
   - 自社管理プロキシの廃止・移行
   - 運用オーバーヘッドの削減

---

## 効果・メリット

### 組織へのメリット

- **運用効率化**: AWS 管理による運用負担軽減
- **セキュリティ強化**: エンタープライズグレードのセキュリティ機能
- **コスト削減**: プロキシインフラ投資・運用費の削減
- **柔軟性**: 既存 Network Firewall ルールの再利用
- **統一管理**: 複数のセキュリティ機能を単一ポリシーで管理

### 技術的なメリット

- **スケーラビリティ**: マネージドサービスとしての自動スケーリング
- **高可用性**: AWS インフラを活用した冗長性確保
- **ロギング・監視**: Amazon S3/CloudWatch との統合

---

## 利用開始方法

### 現在の提供状況

- **利用可能リージョン**: 米国東部（オハイオ）us-east-2
- **提供状態**: パブリックプレビュー中
- **料金**: プレビュー期間中は無料

### 今後の展開予定

- 他リージョンへの拡大
- GA（一般提供）への移行

---

## まとめ

### AWS Network Firewall の新展開

- **統合のメリット**: 独立製品から Network Firewall 統合機能へ
- **ユースケース拡大**: 透過型 + 明示的プロキシの併用が可能に
- **企業向け**: 集中化されたセキュリティ制御と DLP 対策に最適
- **次のステップ**: パブリックプレビューで評価・テスト開始

### 検討のポイント

1. 自社のセキュリティアーキテクチャでの適用性評価
2. 既存プロキシシステムからの移行計画
3. Network Firewall ルール統一による効果測定
