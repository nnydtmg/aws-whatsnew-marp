# AWS Agent Registryが一般提供開始
エージェント検出とガバナンスの集中管理

**発表日: 2026年8月31日**

---

## 概要

### AWS Agent Registry の3つの主要特徴

- **集中管理**: 組織全体のエージェント、ツール、スキル、MCPサーバーを一元管理
- **ガバナンス**: 複数アカウント対応、承認ワークフロー、IAMベースのアクセス制御
- **再利用性**: 既存資産の検出と活用で開発効率を向上

### 利用可能なリージョン

- US East (N. Virginia)
- US West (Oregon)
- Europe (Ireland)
- Asia Pacific (Tokyo)
- Asia Pacific (Sydney)

---

## 前提・背景

### 市場の課題

- **エージェント・ツールの分散**: 各チームが独立してエージェントを構築
- **重複開発**: 既存のエージェント・ツールの発見が困難
- **ガバナンスの欠落**: 組織全体でのコンプライアンス・セキュリティ管理が不十分

### 関連動向

- AWS AgentCore の成長に伴い、エージェント管理の複雑化
- Southwest Airlines など大企業がエンタープライズ規模のエージェント管理を要求
- MCP (Model Context Protocol) サーバーの普及

---

## 主な機能

### 1. 検出・管理機能

- **セマンティック・キーワード検索**: 自然言語で必要なエージェント・ツールを検出
- **URL ベース自動検出**: MCP サーバーやエージェントエンドポイントからメタデータを自動取得
- **複数インターフェース**: コンソール、CLI、SDK、IDE（Kiro）から直接アクセス

### 2. ガバナンス・セキュリティ

- **承認ワークフロー**: ドラフト → 承認待ち → 公開の段階的管理
- **IAM ポリシー**: 登録・検出のアクセス制御
- **CloudTrail 監査**: すべてのアクセスと管理操作を記録

---

## インフラストラクチャ・コード対応

### コード管理

- **AWS CloudFormation**: レジストリをコードで定義・管理
- **Terraform**: インフラストラクチャ・アズ・コード対応
- **AWS CDK**: プログラマティックな定義が可能

### 組織横断的な共有

- **AWS RAM (Resource Access Manager)**: アカウント間でレジストリを共有
- **自動検出**: AgentCore ランタイム・ゲートウェイ上のエージェントを自動インデックス
- **タグ付け**: コスト配分、アクセス制御、組織化に対応

---

## 利用シーン・メリット

### 開発チーム向け

- 既存エージェント・ツールの検出で開発時間を短縮
- IDE から直接レジストリにアクセス可能
- 重複開発を防止

### 管理者・ガバナンス向け

- 組織全体のエージェント・ツール・スキルを一元管理
- 承認ワークフローでセキュリティ・コンプライアンスを強化
- CloudTrail による完全な監査証跡

### エンタープライズ向け

- 複数アカウント対応で大規模組織に対応
- 自動検出で管理負荷を軽減
- カスタムメタデータでコスト・所有権・コンプライアンス状況を追跡

---

## ユースケース

### Southwest Airlines の例

- エンタープライズ規模のエージェント・カタログを構築
- 複数プラットフォーム間での統一的なガバナンス
- 標準化された所有権メタデータとポリシー強制で「エージェント・スプロール」を防止

### Informatica・Check Point の統合

- Informatica: ホストされた MCP サーバーをレジストリから検出・利用
- Check Point: AgentCore ワークロードのセキュリティ・コンプライアンス評価を自動化

---

## ロードマップ・今後の展開

### ガバナンス強化

- セキュリティ・コンプライアンス・重複排除の評価を承認ワークフローに統合
- リソースのバージョニングと完全な監査証跡

### 検出・インベントリ拡張

- EC2、EKS、ECS 上のリソースを自動検出
- 外部システムとのフェデレーション連携

### ユーザー体験向上

- スタンドアロン Web アプリケーション（SSO 認証対応）
- パブリック・レジストリで顧客・パートナーにエージェント機能を公開

---

## まとめ

### AWS Agent Registry が解決する課題

- **エージェント・ツール・スキルの検出**: 組織全体の資産を一元管理
- **ガバナンスの実装**: 承認ワークフロー、IAM、監査で企業要件に対応
- **スケーラビリティ**: 複数アカウント、自動検出で大規模組織に対応

### 次のステップ

1. AWS Agent Registry コンソールで試験的に利用開始
2. 既存エージェント・ツールをレジストリに登録
3. 承認ワークフロー・タグ付けルールを定義
4. 組織全体への展開を計画
