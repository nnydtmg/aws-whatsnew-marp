# AWS Backup が Amazon S3 のバックアップデータへの直接アクセスに対応

S3 アクセスポイント経由で復旧データに直接アクセス可能に

**発表日: 2026年8月6日**

---

## 概要

### 3つの主要な改善点

- **直接アクセス機能**: 復旧を開始することなく、S3 アクセスポイント経由でバックアップデータへの読み取り専用アクセスが可能
- **標準 S3 API 対応**: GetObject、HeadObject、ListObjectsV2 などの標準的な S3 操作でバックアップデータを利用可能
- **複数のユースケース対応**: ターゲット指定ファイル復旧、データ検証、コンプライアンス監査、フォレンジック調査が実現

---

## 前提・背景

### バックアップデータアクセスの課題

- 従来は復旧ポイントにアクセスするため、全体復旧を開始する必要があった
- 特定ファイルの検証やコンプライアンス監査に時間がかかる
- バックアップデータを一時的に活用することが困難

### S3 バックアップの重要性の高まり

- 2026年、Amazon S3 は企業のデータ基盤として中核的な役割を担う
- S3 のデータ容量は年率 35% で成長（LLM・リアルタイム分析による需要増加）
- バックアップの迅速なアクセスと検証がビジネス要件に

---

## 主な機能

### 1. S3 アクセスポイントによる直接アクセス

- 復旧ポイント用の **S3 アクセスポイント** を作成
- 復旧を開始せず、読み取り専用で直接アクセス可能
- バックアップデータは保護されたままの状態を維持

### 2. 復旧ポイント対応

- **スナップショット**: 特定時点のスナップショット復旧ポイント
- **継続的バックアップ**: ポイントインタイム復旧ポイント
- 両方の形式に対応

### 3. 保存場所対応

- 標準バックアップコンテナに保存されたデータ
- 論理的にエアギャップされたコンテナに保存されたデータ

---

## 利用方法と対応機能

### アクセスポイント作成方法

- **AWS Backup コンソール**: GUI で簡単に作成
- **AWS Backup API**: プログラマティックなアクセスポイント管理
- **AWS CLI**: スクリプトによる自動化が可能

### 標準 S3 操作で利用可能

| 操作 | 説明 |
|-----|------|
| GetObject | 個別のオブジェクトを取得 |
| HeadObject | オブジェクトメタデータを確認 |
| ListObjectsV2 | バックアップ内のオブジェクト一覧を取得 |

---

## クロスアカウント・クロスリージョン対応

### アカウント間での復旧ポイント共有

- **AWS Resource Access Manager**: アカウント間でのリソース共有
- **Multi-party approval**: 複数の承認プロセスに対応
- セキュアなコラボレーション環境を実現

### アクティブなアクセスポイントの保護

- アクセスポイント作成中は復旧ポイント削除を禁止
- バックアップデータの削除から自動保護
- データ整合性の確保

---

## ユースケース

### 1. ターゲット指定ファイル復旧

- 全体復旧不要で特定ファイルのみ検証・復旧
- 復旧時間の大幅短縮
- リソース効率の向上

### 2. データ検証・監査

- バックアップの品質を事前確認
- コンプライアンス監査をスムーズに実施
- バックアップの信頼性を検証

### 3. フォレンジック調査

- インシデント発生時の原因調査を高速化
- 特定時点のデータ状態を迅速に確認
- セキュリティ対応の効率化

---

## 対象組織

### 活用推奨組織

- **エンタープライズ組織**: バックアップデータへの迅速なアクセスが必要
- **規制業界**: コンプライアンス要件が厳しい金融・医療・製造
- **データ検証重視**: フォレンジック調査を定期的に実施する必要がある組織

### 期待される効果

- バックアップ復旧時間の短縮
- 監査・検証プロセスの効率化
- セキュリティ対応の迅速化
- 全体復旧コストの削減

---

## 利用可能リージョン

- リージョン別の対応状況は AWS Backup ドキュメントで確認
- 段階的な展開が予定されている
