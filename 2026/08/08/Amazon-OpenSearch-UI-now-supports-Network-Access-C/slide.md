# Amazon OpenSearch UIがネットワークアクセス制御に対応

Amazon OpenSearch UI now supports Network Access Control

**発表日: 2026年8月6日**

---

## 概要

### 何が変わったか

- **IAM条件キーによるアクセス制御**: aws:SourceVpce、aws:SourceVpc、aws:SourceIp を使用して、承認されたネットワークのみへのアクセスを制限
- **複数レベルの制御**: アイデンティティベースポリシー、VPCエンドポイントポリシー、リソース制御ポリシー（RCP）の3つのレベルで実装可能
- **認証前のブロック**: リソース制御ポリシーでオフネットワークユーザーを認証前にブロック
- **全リージョン対応**: OpenSearch UIが利用可能なすべてのAWSリージョンで利用可能

---

## 前提・背景

### セキュリティ対策の課題

- 企業データにアクセスするユーザーのネットワークを制御することが重要
- IAMポリシーだけでなく、ネットワークレベルのセキュリティが必要
- AWS環境全体での一貫したセキュリティポリシーの実装が必要

### Amazon OpenSearch Service のセキュリティレイヤー

- **ネットワークレイヤー**: リクエストがドメインに到達するかどうかを決定
- **ドメインアクセスポリシー**: リクエストがドメインエンドポイントに到達後の制御
- **きめ細かいアクセス制御**: インデックス、ドキュメント、フィールドレベルの制御

---

## 主な機能と改善

### IAM条件キーによるアクセス制限

- **aws:SourceVpce**: VPCエンドポイント経由のアクセスのみを許可
- **aws:SourceVpc**: 特定のVPC からのアクセスのみを許可
- **aws:SourceIp**: 特定のIPアドレスからのアクセスのみを許可

### 3つの実装レベル

1. **アイデンティティベースポリシー**: 特定のプリンシパル向けに細かく設定
2. **VPCエンドポイントポリシー**: VPCエンドポイント経由のアクセスを制御
3. **リソース制御ポリシー（RCP）**: 認証の前段階でアクセスを制御

---

## 実装パターン

### ユースケース: 企業ネットワーク内のみアクセス許可

```
認可されたVPCからのリクエスト
     ↓
✅ OpenSearch UIにアクセス可能
     ↓
コンテンツの取得と操作

オフネットワークからのリクエスト
     ↓
❌ リソース制御ポリシーで即座にブロック
```

### セキュリティメリット

- **多層防御**: ネットワーク → IAM → きめ細かいアクセス制御
- **認証前制御**: 不正アクセスの試みを早期に遮断
- **コンプライアンス**: 企業のセキュリティ要件を満たす
- **一貫性**: AWS環境全体での統一されたデータペリメータ実装

---

## 効果・メリット

### セキュリティの強化

- 承認されたネットワークからのアクセスのみを許可
- 不正アクセスのリスク低減
- エンタープライズレベルのセキュリティ態勢構築

### 運用の効率化

- IAMポリシーとの組み合わせで柔軟に制御
- 複数レベルでのポリシー設定が可能
- OpenSearch UI の全リージョンで統一された設定

### コンプライアンス対応

- データペリメータ戦略の実装
- ネットワーク分離要件への対応
- 監査ログによるアクセス履歴の管理

---

## ユースケース

### 1. 企業専用ネットワーク環境

- VPC内のクライアントからのアクセスのみ許可
- リモートワーカーはVPN経由でアクセス
- オフィスネットワークのIPアドレス範囲を指定

### 2. マルチテナント環境

- テナントごとに異なるVPCエンドポイントを設定
- 各テナント専用のアクセスポリシーを実装
- きめ細かいアクセス制御で データ分離を強化

### 3. 開発・本番分離

- 開発環境と本番環境で異なるVPCを使用
- 本番環境へのアクセスは制限されたネットワークから
- アクセスポリシーで環境を明確に分離

- Amazon OpenSearch UI がネットワークアクセス制御に対応

- 複数レベルのセキュリティポリシー実装が可能
