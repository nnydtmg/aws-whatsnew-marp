# AWS Resilience Hub が推奨レジリエンステストを提供開始

AWS Resilience Hub now provides recommended resilience tests

**What's New** | 2026-08-03T19:02:58

---

## 概要

- AWS Resilience Hubの推奨レジリエンステスト機能により、プラットフォームエンジニアリングおよびサイト信頼性エンジニアリングチームは、既知の障害シナリオに対するサービスの対応と回復を検証できるようになりました。
- このテストはFISを活用して自動的に障害を注入し、詳細なレポートを生成します。

---

## 前提・背景

### アプリケーション信頼性の課題

- インフラストラクチャの複雑化に伴い、障害シナリオの検証が重要
- 本番環境での予期しない障害を事前に検出する必要性
- RPO/RTO目標の達成と検証
- 信頼性スコアに基づく継続的な改善の必要性

### AWS Resilience Hubの進化

- 次世代型 Resilience Hub の登場
- AI駆動の障害モード評価機能
- 自動依存関係検出機能
- 推奨テストの自動生成

---

## 変更内容・新機能

<!-- _class: small -->

### 推奨レジリエンステスト機能

- AWS Resilience Hubが推奨レジリエンステストを提供
- サービスアーキテクチャに基づいて事前設定されたテストを自動生成
- AWS Fault Injection Service (FIS)を活用した制御された障害注入

### 検証可能な障害シナリオ

- 可用性ゾーン(AZ)障害
- リージョン間の障害
- 依存関係障害
- リソースの故障
- ネットワーク遅延・断絶

### 自動レポート生成

- テスト実行結果の自動評価
- アラーム評価と回復目標に基づく合格/不合格判定
- 詳細なテストレポートの自動生成
- レジリエンススコアの計算

---

## 効果・メリット

### 運用効率の向上

- テストケース作成の自動化
- マニュアルテスト作業の削減
- コンソール内での統合実行（外部ツール不要）

### 信頼性の向上

- 本番環境での障害リスク低減
- 予期しない障害の早期発見
- RPO/RTO目標の達成確認

### チーム間の連携強化

- プラットフォームエンジニアリングチームの自動テスト活用
- SRE (Site Reliability Engineer) チームによる定期検証
- 標準運用手順(SOP)の自動確認

---

## ユースケース

### 1. マイクロサービスの信頼性検証

多数のマイクロサービスで構成されたアプリケーションの、サービス間依存関係の障害検証

### 2. 災害復旧計画の検証

リージョン間フェイルオーバーのシナリオテストと RTO/RPO 目標の達成確認

### 3. コンプライアンス要件への対応

金融機関や医療機関での定期的な障害テストと監査ログの自動生成

### 4. デプロイ前の信頼性評価

アーキテクチャ変更やアップグレード前の包括的な影響分析

## まとめ

### AWS Resilience Hub の位置づけ

- アプリケーション信頼性の中心的プラットフォーム
- AI駆動の自動評価と推奨
- 推奨レジリエンステストによる継続的な検証
- 15のAWSリージョンでの利用可能

### 次のステップ

1. AWS Resilience Hub への既存アプリケーションのオンボーディング
2. 推奨レジリエンステストの実行と結果確認
3. レジリエンススコアの改善計画立案
