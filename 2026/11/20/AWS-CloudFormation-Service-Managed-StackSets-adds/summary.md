## 要約

AWS CloudFormation のサービス管理型 StackSets にカスタム実行ロールが追加され、各ターゲットアカウントで権限をスコープできるようになりました。あわせてネストスタック、マクロ、変換も利用可能になり、組織全体へ安全にインフラを展開できます。

## 詳細

AWS CloudFormation StackSets が、サービス管理型スタックセット向けのカスタム実行ロールをサポートしました。これにより、各ターゲット AWS アカウントで StackSets が使用する権限をスコープできます。StackSets は、ネットワーキングやセキュリティ設定などの同一インフラを、数千のアカウントとリージョンへ一度の操作でデプロイします。カスタム実行ロールを使うと、サービス管理型スタックセットでネストスタック、マクロ、変換も利用でき、個別スタック向けの再利用可能なテンプレートを組織全体に展開できます。デフォルトでは、サービス管理型スタックセットは追加設定なしでテンプレート内の任意リソースをプロビジョニングできるロールを各アカウントで使用します。このデフォルトロールは引き続き利用可能です。新たに IAM ロール（実行ロール）を定義するテンプレートを提供すると、StackSets がデプロイ前に各アカウントへそのロールを作成します。例えば Amazon S3 バケットを作成するスタックセットでは、CloudFormation と Amazon S3 の権限に限定した実行ロールを使えます。実行ロールテンプレートを更新すると、デプロイ済みの全アカウントでロールが更新されます。開始するには、CloudFormation コンソールでスタックセット作成時に「Set execution role」を選択するか、AWS CLI または AWS SDKs を使用します。本機能は追加料金なしで、すべての商用 AWS リージョン、AWS GovCloud (US) リージョン、中国リージョンで利用できます。注意点として、カスタム実行ロールへ切り替えてもデフォルトの AdministratorAccess 実行ロールはメンバーアカウントから自動削除されません。最小権限を徹底する場合は、カスタムロールの動作確認後に各メンバーアカウントでデフォルトロールを削除してください。ブートストラップスタックはメンバーアカウントごとに 1 回、パーティションのホームリージョン（商用は us-east-1、中国は cn-north-1）に作成され、名前は stacksets-exec-role-stack- です。以降、そのメンバーアカウントでの作成・更新・削除はすべてカスタムロールで実行されます。ワークロードテンプレートで transforms やマクロ（SAM テンプレートなど）を使う場合は、スタックセット作成時に CAPABILITY_NAMED_IAM と CAPABILITY_AUTO_EXPAND の両方を渡します。実行ロールテンプレート自体はネストスタックや変換を含められません。
