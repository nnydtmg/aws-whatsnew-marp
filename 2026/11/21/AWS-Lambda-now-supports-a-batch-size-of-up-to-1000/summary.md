# AWS LambdaがAmazon SQS FIFOキューでバッチサイズ最大10,000件をサポート

AWS Lambda now supports a batch size of up to 10,000 messages for Amazon SQS FIFO queues

**カテゴリ:** What's New
**公開日:** 2026-11-20T19:00:00
**元記事:** [AWS What's New](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-10K-batch-size-SQSFIFO/)

このページでは、AWS What's Newで発表された「AWS Lambda now supports a batch size of up to 10,000 messages for Amazon SQS FIFO queues」の内容を日本語で要約し、スライド形式で確認できます。

---

## 要約

AWS Lambdaは、プロビジョニングモードのAmazon SQS FIFOキューのイベントソースマッピングにおいて、バッチサイズを最大10,000件まで拡大しました。これまでは最大10件だったため、厳密な順序が必要な高ボリュームワークロードでは呼び出し数の増加や独自バッファの追加が必要でした。本機能により、金融取引・注文処理・在庫更新などの順序付きワークロードをより少ない呼び出しで処理できるようになります。メッセージグループ内の順序は継続して保持されます。

## このアップデートで何が変わったか

プロビジョニングモードでは、イベントポーラーの最小数・最大数を設定してスループットを制御できます。これまではバッチサイズ上限10件の制限により、呼び出しのスケールアウトや独自バッファロジックが必要で、運用負荷とコストが増加していました。本更新により、アプリケーションを再構成せずに大量の順序付きメッセージを少ない呼び出しで処理できます。

対象ワークロード: 金融取引、注文処理、在庫更新など、厳密な順序と重複排除が必要な高ボリューム処理。

## 対象ユーザー

対象ワークロード: 金融取引、注文処理、在庫更新など、厳密な順序と重複排除が必要な高ボリューム処理。

## 詳細

AWS Lambdaは、プロビジョニングモードのAmazon SQS FIFOキューのイベントソースマッピング（ESM）において、バッチサイズを以前の10件から10,000件まで拡大しました。バッチ処理ウィンドウは最大300秒まで設定可能で、各メッセージグループ内の順序は継続して保持されます。

プロビジョニングモードでは、イベントポーラーの最小数・最大数を設定してスループットを制御できます。これまではバッチサイズ上限10件の制限により、呼び出しのスケールアウトや独自バッファロジックが必要で、運用負荷とコストが増加していました。本更新により、アプリケーションを再構成せずに大量の順序付きメッセージを少ない呼び出しで処理できます。

対象ワークロード: 金融取引、注文処理、在庫更新など、厳密な順序と重複排除が必要な高ボリューム処理。

利用方法: Lambda コンソール、AWS CLI、AWS SDKs、AWS CloudFormation、AWS CDK、AWS SAM で新規・既存ESMを設定可能。Kiro、Claude Code、Codex などのコーディングアシスタントと Agent Toolkit for AWS も利用可能。

提供リージョン: すべてのAWS商用リージョン。プロビジョニングモードのSQS FIFO ESMで利用可能。
